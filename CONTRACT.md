# Brief — contract

A two-minute, phone-first news reader. World news through a US lens, plus an Economy tab
and running Storylines. Zero build step, zero npm packages. Static site + one scheduled job.

## Repo layout

```
docs/                      # the PWA, served as-is by GitHub Pages ("deploy from branch, /docs")
  index.html
  app.js                   # vanilla JS, ES modules OK, no bundler
  styles.css
  sw.js                    # cache shell + last data for offline
  manifest.webmanifest
  icon.svg, icon-192.png, icon-512.png, apple-touch-icon.png  (PNGs generated by job/make-icons.mjs, no deps)
  data/brief.json          # today's brief (schema below) — written by the job
  data/storylines.json     # persistent threads — written by the job
  data/history/YYYY-MM-DD.json  # copy of each day's brief.json (kept 30 days)
job/
  build-brief.mjs          # Node 24, ZERO dependencies (built-in fetch, zlib, fs only)
  brief.schema.json        # JSON Schema for the model's structured output (also validates locally)
  feeds.json               # feed list, editable by Harrison
  fixtures/                # synthetic RSS XML + a canned model response for offline tests (fictional content)
  make-icons.mjs           # writes the PNG icons with built-in zlib (no packages)
.github/workflows/brief.yml   # cron 13:00 UTC daily + workflow_dispatch; commits docs/data/*
CONTRACT.md
README.md
```

## Runtime rules

- The laptop is never a server. The job runs in GitHub Actions. The site is static.
- The job MUST NOT overwrite `docs/data/brief.json` with anything that fails schema validation.
  On any failure it exits non-zero and leaves yesterday's files untouched.
- Every network fetch in the job has a timeout (10 s) and is fail-soft: one dead feed never
  kills the run. Econ indicators and Kalshi odds are optional; missing ones are omitted, not faked.
- No third-party JS or CSS on the site except the Archivo font from Google Fonts (same as Wins).
- No analytics, no tracking, no cookies. Read state lives in localStorage only.

## docs/data/brief.json

```jsonc
{
  "version": 1,
  "generated_at": "2026-09-27T13:04:12Z",
  "date": "2026-09-27",                      // America/Los_Angeles calendar date of the run
  "model": "claude-opus-5",
  "today": [                                 // 3–5 items. World-first, US lens.
    {
      "id": "2026-09-27-t1",                 // stable within the day
      "headline": "≤ 80 chars, plain, no clickbait",
      "what_happened": "1–2 sentences.",
      "us_angle": "1–2 sentences: why this touches the US.",
      "whats_new": "1 sentence: what changed since yesterday, or 'New today.'",
      "region": "Europe | Middle East | Asia | Americas | Africa | US | Global",
      "storyline_id": "sl-ukraine-war" ,     // or null
      "sources": [{ "outlet": "AP", "title": "…", "url": "https://…" }]   // 1–3
    }
  ],
  "economy": {
    "read": "One short paragraph (≤ 60 words): the state of the US economy this morning.",
    "indicators": [                          // whatever fetched OK; omit failures
      { "key": "fedfunds", "label": "Fed funds", "value": "4.25–4.50", "unit": "%", "as_of": "2026-09-17", "change": "unch", "note": "≤ 12 words" }
    ],
    "fed": {
      "next_meeting": "2026-10-29",          // or null
      "odds": [{ "label": "Cut 25bp", "prob": 0.62 }],   // from Kalshi if fetched, else []
      "note": "≤ 20 words"
    },
    "week_ahead": [                          // 0–5 upcoming US data releases / events
      { "date": "2026-09-30", "event": "JOLTS (Aug)", "why_it_matters": "≤ 15 words" }
    ],
    "items": [ /* 0–3 econ news items, same shape as today[] */ ]
  },
  "washington": [ /* 0–3 items, same shape as today[]: votes, rules, court rulings */ ],
  "storyline_updates": [                     // which threads moved today (mirrors storylines.json)
    { "storyline_id": "sl-ukraine-war", "update": "1 sentence" }
  ]
}
```

Item text budgets are hard limits: the whole Today tab must read in under 60 seconds.

## docs/data/storylines.json

```jsonc
{
  "version": 1,
  "updated_at": "2026-09-27T13:04:12Z",
  "storylines": [
    {
      "id": "sl-ukraine-war",                // slug, stable forever
      "title": "≤ 50 chars",
      "summary": "≤ 40 words: where things stand now (rewritten each time it moves)",
      "status": "active",                    // active | dormant (no event in 14 days) 
      "first_seen": "2026-09-01",
      "last_updated": "2026-09-27",
      "events": [                            // newest first, keep ≤ 20
        { "date": "2026-09-27", "text": "≤ 25 words", "url": "https://…" }
      ]
    }
  ]
}
```

Max 12 active storylines. The job passes the previous storylines.json to the model, which
returns the full updated list (append events, rewrite summaries, mark dormant, create new).

## Client read state (localStorage key `brief.state.v1`)

```jsonc
{ "last_visit": "2026-09-26T16:12:00Z", "seen": { "2026-09-27-t1": true }, "tab": "today" }
```

- A storyline shows a "new" dot when `last_updated` > `last_visit` (date compare).
- An item is dimmed once tapped/expanded (seen). Seen map resets when `date` changes.
- `last_visit` updates on page hide/unload, not on load, so today's dots survive the first open.

## Claude call (raw HTTPS, no SDK — the project has no packages by design)

- POST https://api.anthropic.com/v1/messages
- headers: `x-api-key`, `anthropic-version: 2023-06-01`, `anthropic-beta: server-side-fallback-2026-07-01`, `content-type: application/json`
- body: `{ model: process.env.BRIEF_MODEL || "claude-opus-5", max_tokens: 16000, fallbacks: "default",
          output_config: { format: { type: "json_schema", schema: <job/brief.schema.json> } },
          system: <stable editorial prompt>, messages: [{ role: "user", content: <dated payload> }] }`
- Do NOT send `thinking` (adaptive is the default on this model) and do NOT send temperature.
- Check `stop_reason`: `end_turn` → parse first text block as JSON and validate; `refusal` or
  `max_tokens` → fail the run (exit 1) with the reason logged. Log `usage` every run.
- Model output schema = brief.json minus `generated_at`/`date`/`model`/`version` (job fills those)
  PLUS a `storylines` array (full updated storylines list). The job splits it into the two files.

## Job inputs per run

1. Feeds from job/feeds.json (RSS 2.0 + Atom). Keep entries from the last 36 h, dedupe by URL
   and near-identical title, cap at 120 entries, each as {outlet, title, url, published, summary≤400 chars}.
2. Econ series via FRED CSV (no key): `https://fred.stlouisfed.org/graph/fredgraph.csv?id=<SERIES>`
   for FEDFUNDS, CPIAUCSL (compute YoY %), UNRATE, DGS10, DGS2, MORTGAGE30US, plus last 2 obs each.
3. Kalshi public markets (no key) for the next FOMC decision; endpoint may change — fail-soft, 5 s timeout.
4. Previous docs/data/storylines.json and previous brief.json (for "what changed").

## Modes

- `node job/build-brief.mjs`            real run (needs ANTHROPIC_API_KEY)
- `node job/build-brief.mjs --fixture`  no network at all: fixtures/feeds/*.xml + fixtures/model-response.json → writes docs/data
- `node job/build-brief.mjs --dry-run`  fetch feeds + econ, print the payload that would be sent, no Claude call, no writes
- `node job/build-brief.mjs --validate` validate docs/data/*.json against the schema, exit 1 on failure
